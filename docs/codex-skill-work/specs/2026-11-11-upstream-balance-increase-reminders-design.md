# 上游站点余额增加提醒设计

## 目标

后台持续按站点查询已配置登录凭据的上游余额。余额高于上次成功查询值时，提醒管理员补记余额中心充值，避免经营历史漏记。提醒在余额中心为该站点成功新增充值记录后自动解除。

## 方案

- 仅从上游站点账号配置读取站点级登录凭据；不使用调度账号逐个查询，避免同站多个 API Key 导致余额显示不一致。
- 后端每 5 分钟按站点查询一次余额，每站每轮至多一次只读余额请求。使用已有登录态；有受支持的 refresh token 时先刷新，只有接口明确表示登录态失效才刷新或重新登录。普通权限错误、网络错误或无效响应不得触发登录循环；失败站点退避重试。
- 按上游协议选择已验证的用户余额接口；首次成功查询只保存基线，不产生提醒。后续余额增加时持久化该站的活动提醒及前后余额。一个站点保留一条活动提醒，多站可同时提醒；重复增加更新同站提醒。
- 新增独立、受管理员认证的实时通知 WebSocket。连接时先下发尚未解除的提醒，变化时推送新建、更新和解除事件。数据库为事实来源，页面关闭期间发现的提醒在下次连接时仍可恢复；前端只展示，不轮询。
- 右下角浮窗可收起，不提供手动关闭入口。成功新增对应站点的余额中心充值记录时，在同一数据库事务内解除该站提醒，并推送解除事件；其他站点提醒不受影响。

## 边界与错误处理

- 不把账号调度状态作为站点轮询条件，也不影响现有账号余额探测与调度。
- 首次样本只建立基线，查询失败不改变基线或提醒状态。
- 余额变化检测使用数值精度容差，避免浮点误差造成误报；实现时结合现有金额精度确认阈值。
- 站点凭据、访问令牌和刷新令牌不得返回前端或写入日志。令牌按现有安全加密能力保护；若上游不支持刷新令牌，则只在登录态失效后使用已保存站点凭据重新登录。
- 充值记录关联按余额中心站点与上游站点的规范化域名完成；无法唯一匹配时不自动解除，保留提醒并记录脱敏诊断信息。

## 验证

- 后端单测覆盖基线初始化、余额增加/不变/下降、认证失败后刷新或登录、非认证失败不重复登录、站点级去重和错误退避。
- 仓储测试覆盖站点状态持久化、活动提醒恢复，以及新增充值记录与解除提醒的事务原子性。
- WebSocket/路由测试覆盖管理员认证、连接初始快照、实时变化推送和页面关闭后重连恢复。
- 前端测试覆盖右下角多站展示、收起/展开、禁止手动关闭，以及解除事件只移除对应站点提醒。
- 完成相关 Go 测试、前端 `pnpm run build` 与 `git diff --check`；不启动本地完整后端、不访问或修改生产数据。

## 单独后续事项

余额增加提醒完成后，独立只读检查现有低余额邮件告警从触发、队列、发送到失败记录的链路，并评估手机端可持续接收的通知方式；不在本功能中更改告警策略、发送配置或生产数据。
