# Sub2API 安卓告警

适用于 Android 8.0 及以上。余额中心探测到低余额或上游倍率变化时生成事件，运维规则识别到上游因余额不足拒绝请求时也会生成事件。首次安装可补收最近 24 小时的告警。手机保存读取进度，网络恢复后接着收取。

## 服务端启用

1. 按仓库发布流程部署包含迁移 `276_mobile_alerts.sql` 的版本。
2. 在受信任的本机用密码管理器生成专用随机口令，例如 32 字节随机值的十六进制字符串。将口令的 SHA-256 十六进制摘要设为应用容器的 `SUB2API_MOBILE_ALERT_TOKEN_SHA256`，通过发布入口应用到所有承接 API 或运行余额探测的应用槽位。仓库 Compose 模板包含该变量，既有服务器 Compose 也须包含对应映射。手机输入原始口令。
3. 在余额中心核对低余额阈值。需要上游调用失败告警时，核对运维监控和账号请求异常规则已启用。采集频率仍由现有探测和运维规则决定。余额不足和倍率变化的手机提醒使用独立状态，现有下一阈值入口仍服务于原提醒链路。

专用口令仅可读取 `GET /api/v1/mobile-alerts?after=<事件编号>`，通过 `Authorization: Bearer` 传输。服务端仅需摘要。替换摘要并应用到应用槽位可撤销旧口令。

## 手机使用

1. 安装 APK。打开 App，输入 HTTPS 站点和专用口令，允许通知，然后点击「保存并开始监控」。Android 13 及以上首次授权后需再点击一次。
2. 点击「发送测试通知」后锁屏。5 秒后检查锁屏、下拉通知栏、声音和振动。手机的锁屏、弹出、免打扰和后台管理设置会影响展示和到达时间。
3. 保留「Sub2API 告警监控」前台服务。服务运行且网络可用时约每 30 秒检查一次。深度休眠、系统限制后台或离线时会延后，手机重启或强制停止后需要重新打开监控。

## 构建 APK

安装 Android SDK Platform 35、Build Tools 35.0.0 以及 JDK 17 或 21。设置 `ANDROID_SDK_ROOT` 与 `JAVA_HOME` 后运行 `./build-apk.sh`。APK 输出到 `build/sub2api-alerts.apk`。默认使用本机调试签名，后续覆盖安装需沿用同一签名。已有专用签名可通过 `SUB2API_ANDROID_KEYSTORE` 传入安全存放的 keystore 路径。
